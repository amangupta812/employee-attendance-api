| 1 | `health` (lines 72-74) | Never pings MongoDB; returns 200 `{"status": "ok"}` unconditionally even when database is unreachable. | Stop MongoDB or disconnect; `GET /health` still returns 200 OK instead of the required 503. | Added `client.admin.command("ping")` in a try/except block; raises `HTTPException(503, "Database unavailable")` on failure. |

| 5 | `create_employee` (lines 77-86) | Check-then-insert race condition on `emp_code`; missing validation that `shift_start != shift_end` (422); missing regex validation on `emp_code` and `email`; sets `created_at` to naive `datetime.now()` and returns it as an ISO string. | Concurrent POSTs with identical `emp_code` both succeed; invalid email or `shift_start == shift_end` returns 201; response schema validation fails because `created_at` is not an integer. | Enforced unique database index on `emp_code` and caught `DuplicateKeyError` to return 409; added Pydantic regex/length constraints; validated `shift_start != shift_end`; stored UTC datetime and serialized `created_at` to integer epoch milliseconds. |

| 10 | Instant / Timestamp Validation (throughout) | Missing validation that client-supplied timestamps (`punched_at`, etc.) are valid integer epoch milliseconds. | Supplying floats, strings, or 10-digit second timestamps is accepted without rejection, corrupting dates in MongoDB. | Defined `StrictInt` with range `100000000000` to `4102444800000` to reject invalid values with 422. |

Also note anything you looked at and decided was **not** a defect, and why:
- **Storing dates and shift times as strings in MongoDB**: In accordance with `DATA_MODEL.md`, calendar dates (`YYYY-MM-DD`) and shift times (`HH:MM`) are deliberately stored as plain strings in IST to avoid time zone coercion, whereas instants are stored as BSON datetimes. This is an intentional design choice, not a defect.
- **Missing `history` and `half_day` in legacy documents**: `DATA_MODEL.md` explicitly documents that legacy seeded records may omit `history` and `half_day`. Treating missing `history` as `[]` and missing `half_day` as `false` is intended behavior.
